## 문제: 추론은 끝났지만 방은 닫히지 않았다

여러 각도에서 촬영한 방 사진으로 공간을 복원했을 때, 최종 결과가 닫힌 방 대신 끊어진 선과 중복 점으로 나타나는 문제가 있었습니다. 서버 로그에는 예외가 없었습니다. 처리가 실패한 것이 아니라, 정상적으로 끝난 처리의 결과가 잘못된 상황이었습니다.

이 글은 **2026년 7월 17일 작성한 재구성 파편화 진단 문서**의 재현 기록을 바탕으로 정리했습니다. 당시 room1과 room4 실사진 사례를 분석한 기록이며, 이 글을 작성하며 GPU 추론을 다시 실행한 결과는 아닙니다.

## 조건과 관찰값

파이프라인은 먼저 3D 구조를 추론하고, 이를 이미지에 투영해 사용자가 수정할 수 있게 한 뒤, 수정된 정보를 다시 3D에 반영하는 흐름입니다.

문제가 나타난 room4 사례에서 단계별 정점과 엣지를 비교했습니다.

| 관찰 지점                  | 정점                  | 엣지 | 고립 정점 |
| -------------------------- | --------------------- | ---- | --------- |
| AI 원본 3D 출력            | 15개, 모두 다른 위치  | 16개 | 0개       |
| 미보정 재현의 최종 출력    | 15개, 고유 위치는 7개 | 9개  | 2개       |
| 수동 보정 사례의 최종 출력 | 16개                  | 8개  | 3개       |

수동 보정 사례에서는 서로 15cm 이내에 있으면서 합쳐지지 않은 정점 쌍도 19개 관찰했습니다. 이 수치는 해당 장면에서의 중복 후보를 설명하기 위한 것이며, 전체 데이터셋의 정확도 지표가 아닙니다.

## 가설: 모델보다 단계 사이의 변환을 확인하자

원본 3D 결과에는 엣지 16개가 있었지만 최종 결과에는 9개만 남았습니다. 따라서 모델을 바꾸기 전에 **3D 결과가 보정용 2D 데이터로 내려가는 구간**을 확인했습니다.

당시에는 3D 코너를 최초로 검출한 뷰 한 곳에만 투영했습니다. 엣지는 양 끝점이 같은 뷰에 함께 투영된 경우에만 보정 화면으로 전달되었습니다.

```text
원본 3D 구조: 엣지 16개
        ↓ 검출 뷰 한 곳에만 코너 투영
보정용 2D 데이터: 엣지 9개
        ↓ 보정 데이터를 사용해 다시 3D 구성
최종 구조: 엣지 9개
```

room4에서는 코너 15개 모두가 한 뷰에만 존재했고, 엣지 16개 중 7개는 두 끝점이 같은 뷰에 나타나지 않아 전달되지 않았습니다. 최종 엣지 개수가 보정용 엣지 개수와 같다는 점이 손실 구간을 특정하는 단서였습니다.

## 수정 방향 1: 한 코너를 여러 뷰에 투영하기

해결 방향은 검출 뷰 하나에 묶여 있던 코너를, 카메라 앞쪽이면서 이미지 범위 안에 투영되는 여러 뷰로 확장하는 것입니다. 엣지 양 끝점이 함께 표현될 기회를 늘려 보정 단계의 정보 손실을 줄이려는 접근입니다.

여기서 사용하는 카메라 전방·이미지 경계 조건은 투영 가능한지를 판단하는 기하 조건입니다. 실제 물체에 의한 가림까지 완전히 판정한다는 의미로 확대해서 해석하지 않습니다.

## 수정 방향 2: 사용자가 추가한 점의 대응 찾기

AI가 만든 점을 이동한 경우에는 원본 정점 ID로 여러 뷰의 결과를 연결할 수 있었습니다. 하지만 사용자가 새로 추가한 점에는 이 ID가 없어, 같은 코너를 여러 사진에서 지정해도 서로 다른 3D 점으로 처리되었습니다.

추가점을 무조건 독립적으로 만드는 대신, 서로 다른 뷰의 광선이 만나는 관계를 이용해 삼각측량하고 대응되는 점을 병합하는 방향을 세웠습니다. 단순히 가깝다는 이유만으로 다른 코너를 합치지 않도록 조건도 필요합니다.

또한 추가점의 깊이를 바닥과 천장 중 하나로만 정하면 벽 위의 코너를 표현하기 어렵습니다. 다중 뷰 삼각측량과 수직 벽 평면 후보를 활용하고, 단일 뷰에서는 평면 교차를 보완 수단으로 사용하는 방향입니다.

## 구현 상태와 검증 범위

원본 진단 문서의 7월 20일 갱신에는 우선순위 1~3의 서버 반영이 완료되었다고 기록되어 있습니다. 반면 뷰를 넘는 엣지 편집은 프런트엔드와의 협의가 필요한 미착수 항목으로 남아 있습니다.

문서에 제시된 **엣지 14개 이상 유지, 고립 정점 0개**는 수정 검증의 목표입니다. 수정 후 실사진에서 달성한 측정값으로 읽어서는 안 됩니다. 후속 구현 계획에서도 room4 실데이터 재현은 별도 수동 검증으로 분리했습니다.

따라서 이 기록으로 말할 수 있는 결과는 **원본 3D에서 보정용 2D로 변환하는 과정의 엣지 손실 원인을 특정했다는 것**입니다. 수정 후 품질 개선 폭은 같은 입력과 조건으로 다시 측정한 결과를 추가해야 합니다.

## 남은 질문

- 미편집 결과와 실제 사용자 보정 결과가 각각 어떤 경로를 타는가?
- 뷰 간 대응을 늘렸을 때 엣지 보존과 오병합은 어떻게 달라지는가?
- 같은 조건의 room1·room4 입력에서 고립 정점과 닫힌 윤곽이 개선되는가?

3D 복원 품질은 모델 출력만의 문제가 아니었습니다. 중간 표현으로 바꾸는 과정에서 무엇을 잃는지, 그리고 사용자의 수정이 어떤 정보를 필요로 하는지까지 함께 확인해야 했습니다.
