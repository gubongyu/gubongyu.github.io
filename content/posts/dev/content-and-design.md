좋아하는 웹사이트의 모습은 시간이 지나며 달라집니다. 하지만 그 안에 쌓인 글까지 다시 작성하고 싶지는 않습니다. 그래서 이 공간은 **글과 화면이 서로 다른 이유로 바뀐다는 것**에서 출발했습니다.

> 이 글은 사이트의 읽기 경험을 보여주는 예제 콘텐츠입니다.

## 콘텐츠의 역할

Markdown에는 제목, 문단, 코드와 이미지처럼 내용의 의미를 기록합니다. 그림자의 크기나 카드의 회전 각도는 글에 넣지 않습니다.

```text
content/                  글과 프로젝트의 원본
src/application/          공개 콘텐츠 조회
src/designs/studio/       화면과 인터랙션
```

이렇게 나누면 글을 추가하기 위해 컴포넌트를 수정할 필요가 없습니다. 새로운 디자인을 만들 때에도 기존 콘텐츠를 그대로 사용할 수 있습니다.

## 화면에 필요한 만큼만 전달하기

목록에는 제목과 요약이 필요하고, 상세 페이지에는 본문이 필요합니다. 각 화면에 필요한 데이터를 미리 정리해 전달하면 화면 코드는 표현에 집중할 수 있습니다.

```ts
type PostSummary = {
  title: string;
  summary: string;
  href: string;
};
```

| 바뀌는 것      | 수정하는 곳 |
| -------------- | ----------- |
| 문장과 제목    | Markdown    |
| 글 목록의 배치 | 페이지 뷰   |
| 배경색과 글꼴  | 디자인 토큰 |

## 작은 경계부터

처음부터 모든 것을 추상화할 필요는 없습니다. 콘텐츠를 읽는 곳, 공개 여부를 결정하는 곳, 화면을 만드는 곳을 나누는 것만으로도 변경의 범위가 선명해집니다.

오래 유지하는 웹사이트를 위해 필요한 것은 앞으로의 모든 기능을 예측하는 일이 아니라, 지금 서로 다른 책임을 구분하는 일이라고 생각합니다.
