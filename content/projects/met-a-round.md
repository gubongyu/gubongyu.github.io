## 사진에서 공간으로

방을 여러 각도에서 촬영한 사진을 바탕으로 벽과 바닥의 구조를 복원하고, 가구를 배치할 수 있는 3D 공간으로 연결하는 프로젝트입니다. 한 장의 사진에서 보이지 않는 공간을 여러 시점의 정보로 보완하는 것이 출발점입니다.

한양대학교 소프트웨어학부 졸업 프로젝트로 진행했으며, 저는 **다중 뷰 기하와 벽선 추출·병합을 이용한 AI·3D Vision 파이프라인**을 맡았습니다. 팀의 백엔드와 클라이언트 작업을 제 개인 구현 범위에 포함하지 않습니다.

위의 스크롤 파이프라인은 사진 입력부터 구조 복원까지의 과정을 10단계로 설명합니다. **미리 준비된 이미지와 기하 데이터를 시각화하는 데모**이며, 이 페이지에서 사진을 업로드하거나 AI 추론을 실행하지는 않습니다.

## 담당한 문제

이미지에서 얻은 깊이와 구조 정보를 하나의 좌표계에 모은다고 곧바로 사용할 수 있는 방이 만들어지지는 않습니다. 가구에 가려진 벽, 서로 겹치는 선, 닫히지 않는 바닥 윤곽과 같은 문제를 정리해야 합니다.

제가 맡은 부분은 여러 시점의 정보를 결합하고, 벽 후보를 추출·병합해 일관된 공간 구조로 연결하는 과정입니다. 파이프라인에서 보여주는 벽선과 평면도는 이 과정을 설명하는 핵심 자료입니다.

## 복원 과정을 나누어 설계하기

첫 구간에서는 사진의 요소와 깊이를 구분하고, 여러 시점에서 얻은 정보를 3D 점군으로 연결합니다. 이어 방의 방향을 정리하고 벽에 해당하는 정보를 평면에서 살펴봅니다.

다음 구간에서는 벽선 후보를 찾고 같은 벽을 나타내는 선을 병합합니다. 정리한 선들이 닫힌 바닥 윤곽을 이루면 높이 정보를 적용해 3D 방 구조를 구성합니다. 미터 단위 복원은 스케일 보정에 사용한 조건에 의존하며, 이 데모만으로 임의의 방에서 실측 정확도가 보장되는 것은 아닙니다.

마지막으로 모서리와 연결 관계를 확인합니다. 결과가 보기 좋은지만이 아니라, 구조가 끊기지 않고 후속 단계에서도 유지되는지가 중요합니다.

## 사용자 보정까지 이어지는 데이터

실제 서비스 흐름에는 AI 결과를 사용자가 2D 화면에서 수정하는 단계가 있습니다. 여기서는 원본 3D 구조, 이미지에 투영된 점과 선, 사용자가 수정한 결과 사이의 대응 관계를 유지해야 합니다.

이 경계를 확인하는 과정에서, AI가 생성한 선이 보정용 투영을 거치며 사라지는 사례를 발견했습니다. 모델의 출력만 살펴보는 것으로는 설명하기 어려운 문제였고, 단계 사이의 데이터 변환을 추적하는 실험으로 이어졌습니다.

프로젝트 하단의 실험 기록에서 재현 사례, 원인과 수정 방향을 따로 설명합니다.

## 시각화와 실제 추론의 범위

웹 랜딩의 3D 시각화는 복원 결과를 이해하고 탐색하기 위한 도구입니다. AI 모델 실행, 웹 시연, 팀의 API 및 클라이언트는 서로 다른 구성 요소입니다.

이 글의 기술 목록도 역할을 구분해 읽을 수 있도록 정리했습니다. Python과 다중 뷰 기하는 AI 처리의 맥락이며, Three.js와 TypeScript는 결과를 설명하는 웹 시각화의 맥락입니다.

## 결과를 기록하는 기준

파이프라인 시연과 실제 실험 결과를 구분해 기록합니다. 재현 데이터가 있는 수치는 해당 장면과 조건을 함께 적고, 수정 목표나 테스트 기대값을 측정된 개선 성과처럼 표현하지 않습니다.

현재 글은 서비스 규모나 종합 정확도를 제시하기보다, 공간 복원 과정과 단계 사이에서 발생한 문제를 어떻게 분석했는지 보여주는 데 초점을 맞춥니다.
