# 콘텐츠 작성과 디자인 변경

## 1. 실제 프로필로 바꾸기

`content/profile/profile.json`의 `main` 항목을 수정합니다. `name`, `handle`, `headline`, `bio`, `status`를 채우고 기술·이력·외부 링크를 추가합니다. 이메일을 공개하지 않으려면 `email` 필드를 생략합니다. 예제 소개를 교체했다면 `sample`을 `false`로 바꿉니다.

```json
{
  "label": "GitHub",
  "url": "https://github.com/YOUR_USERNAME"
}
```

위 항목을 `socialLinks` 배열에 넣으면 소개·푸터·터미널에 반영됩니다. 프로필 객체는 한 개만 유지합니다.

## 2. 글 작성

개발 글은 `content/posts/dev/`, 기타 글은 `content/posts/life/`에 `.md` 파일을 추가합니다.

```yaml
---
id: post-my-first-note
slug: my-first-note
title: 첫 번째 기록
summary: 목록과 검색에 표시할 간단한 설명입니다.
section: dev
publishedAt: '2026-10-02T09:00:00+09:00'
draft: true
sample: false
tags: [Astro, 기록]
relatedProjects: []
---

첫 문단을 작성합니다.

## 시작하게 된 이유

본문을 작성합니다.
```

- `id`는 사이트 전체에서 고유한 안정 식별자입니다. 발행 후 유지합니다.
- `slug`는 같은 종류의 콘텐츠에서 고유해야 하며 공개 주소에 사용됩니다. 제목 변경으로 slug를 바꾸지 않습니다.
- `section`은 파일이 위치한 `dev` 또는 `life` 폴더와 일치해야 합니다.
- 날짜는 따옴표와 시간대를 포함합니다. `draft: true` 또는 미래 날짜의 콘텐츠는 공개 산출물에서 제외됩니다.
- 태그에 `/`, `\`, `?`, `#`, `%` 같은 경로 문자를 넣지 않습니다.
- 페이지가 제목을 `h1`으로 만들므로 본문 제목은 `##`부터 시작합니다.
- 목차와 읽기 시간은 생성됩니다. 읽기 시간은 본문 문자 수를 이용한 근사값입니다.

초안은 로컬 개발 화면에서도 기본으로 제외됩니다. 확인하려면 날짜를 현재 이전으로 지정하고 로컬에서 `draft: false`로 바꿉니다. 공개 빌드에 포함될 값인지 커밋 전에 확인하세요. 전용 초안 미리보기 화면은 아직 제공하지 않습니다.

## 3. 이미지

이미지는 `content/assets/`에 두고 Markdown 파일 기준 상대 경로로 참조합니다. 원본의 alt 텍스트는 반드시 작성합니다.

```md
![프로젝트의 검색 결과 화면](../../assets/search-result.png)
```

위 경로는 `content/posts/dev/`에 있는 글 기준입니다. 빌드는 이미지 존재와 alt 텍스트를 확인하고 Astro가 본문 이미지 처리를 담당합니다. 이미지 너비는 본문 안에 제한됩니다. 외부 이미지 주소의 지속성은 별도로 관리해야 합니다.

현재 목록의 예제 그래픽은 디자인의 `ProjectCard.astro`에 있습니다. 실제 프로젝트 화면을 목록 커버로 보여주는 기능은 별도의 이미지 필드와 presenter를 추가해 확장할 수 있습니다. 콘텐츠에 컴포넌트 import나 인라인 스타일을 넣지 않습니다.

## 4. 프로젝트

`content/projects/`에 기존 예제를 복사해 작성합니다. 글의 공통 메타데이터 외에 다음 필드를 사용합니다.

```yaml
status: building # building | released | archived
featured: true
role: 개인 프로젝트 · 기획과 개발
stack: [Astro, TypeScript]
startedAt: '2026-10'
repositoryUrl: https://github.com/YOUR_USERNAME/REPOSITORY
demoUrl: https://YOUR_DOMAIN
relatedPosts: [post-my-first-note]
```

실제 주소가 없으면 `repositoryUrl`, `demoUrl`을 생략합니다. `featured: true`인 프로젝트 중 최신 두 개가 홈에 표시됩니다. 본문에는 배경·문제·역할·구현·결과를 자유롭게 기록합니다.

`relatedPosts`와 글의 `relatedProjects`에는 slug가 아닌 ID를 사용합니다. 현재 각 방향의 관계를 명시적으로 작성합니다. 참조 대상이 없으면 빌드가 실패하고, 비공개 대상은 화면에서 제외됩니다.

## 5. 외부 블로그

`content/external-blogs.json`에 다음 형태로 추가합니다. 빈 배열이면 홈의 외부 블로그 영역을 생략합니다.

```json
[
  {
    "id": "my-external-blog",
    "title": "다른 공간의 기록",
    "description": "이곳에서 다루는 이야기의 짧은 소개",
    "url": "https://YOUR_BLOG",
    "section": "life"
  }
]
```

이 기능은 블로그 소개 링크입니다. 외부 글 본문을 복사하거나 검색에 자동 포함하지 않습니다.

## 6. 디자인 수정

색·여백·서체는 `theme.css`, 본문은 `prose.css`, 배치는 `views/`에서 수정합니다. 3D는 `hero/scene.ts`, 포스터는 `public/designs/studio/desk.svg`에서 관리합니다.

전면 개편 시 `designs/<새이름>/`에 뷰를 만들고 `presentation/active-design.ts`의 정적 export를 바꿉니다. 각 뷰의 props, 상세 페이지의 본문 슬롯, 하나의 `main#main-content`, 검색·필터·터미널의 `data-*` 연결점을 유지합니다. 다른 디자인의 내부 컴포넌트를 직접 import하지 않습니다.

`npm run check`는 타입과 import 경계를 검사합니다. `npm test`, `npm run build`, `npm run test:e2e`로 공개 정책·링크·검색·브라우저 흐름을 확인합니다. 디자인만 변경할 때는 콘텐츠 원본과 공개 URL을 함께 수정하지 않습니다.
